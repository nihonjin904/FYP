# 01-01-PLAN.md — Phase 1: Boss 危攻擊 AnimNotify 設定

## Goal

在 BP_SekiroEnemy 的危攻擊 Montage 的**武器命中時機**加入 `AN_PerilousHit` AnimNotify，

在 AnimBlueprint 的 Event Graph 監聽並呼叫 C++ 函數 `PerformPerilousHitCheck()`，

令危攻擊無法被玩家格擋。

---

## 重要背景知識（Executor 必讀）

**現有 C++ 邏輯（已完成）：**

```
函數:   USekiroCombatComponent::PerformPerilousHitCheck()
位置:   Line 577 in SekiroCombatComponent.cpp
Tag:    Attack.Perilous → SekiroDeflectComponent::TryParry() 強制返回 Failed
效果:   無條件造成 PerilousAttackDamage + PerilousPostureDamage
```

**現有觸發機制（Timer-based，需被 AnimNotify 替代）：**

```cpp
// Line 87-90 in SekiroCombatComponent.cpp
GetWorld()->GetTimerManager().SetTimer(
    PerilousAttackHitHandle,
    [this]() { PerformPerilousHitCheck(); },
    0.3f, false);  // ← 固定 0.3 秒後觸發，與動畫不同步
```

**AnimNotify 的優勢：** 替換 Timer 後，命中判定與動畫幀完全同步，危字時機也會更準確。

## Tasks

### Task 1 — 在全部 5 個危攻擊 Montage 加入 `AN_PerilousHit` AnimNotify

<read_first>
在 Content Browser 找到以下 5 個 Montage assets，全部都要操作：
1. AM_Perilous_Slash_Patchouli
2. AM_Perilous_Thrust_Patchouli
3. AM_PerilousAttack_Slash
4. AM_PerilousAttack_Sweep
5. AM_PerilousAttack_Thrust
</read_first>

<action>
**對每一個 Montage 重複以下步驟（共 5 次）：**

**步驟 1：打開 Montage**
1. 在 **Content Browser** 搜尋 Montage 名稱（例如 `AM_Perilous_Slash_Patchouli`）
2. **雙擊**打開，進入 **Anim Montage Editor**

**步驟 2：找到命中時機**
3. 按 **空格鍵** 播放動畫
4. 看武器/拳頭「接觸到玩家位置」的那一幀
   - **Slash（橫劈）類：** 通常在 40%~55% 位置（揮出去的那一刻）
   - **Thrust（刺擊）類：** 通常在 35%~50% 位置（刺出去的前端）
   - **Sweep（掃擊）類：** 通常在 45%~60% 位置（掃到最遠點）
5. 記住大概時間位置

**步驟 3：加入 AnimNotify**
6. 在 timeline 下方的 **"Notifies"** 軌道 → 找到武器命中的時間點
7. **右鍵點擊** 該時間點
8. 選擇 **"Add Notify..."**
9. 搜尋 `AN_PerilousHit`
   - **第一個 Montage：** 沒有的話選 **"New Notify..."** 輸入 `AN_PerilousHit`
   - **第 2~5 個 Montage：** `AN_PerilousHit` 已存在，直接選取它
10. 按 **Ctrl+S** 儲存

**重複上述步驟給剩餘 4 個 Montage。**
</action>

<acceptance_criteria>
- 以下 5 個 Montage 的 Notifies 軌道各有一個 "AN_PerilousHit" 橙色標記：
  - AM_Perilous_Slash_Patchouli ✓
  - AM_Perilous_Thrust_Patchouli ✓
  - AM_PerilousAttack_Slash ✓
  - AM_PerilousAttack_Sweep ✓
  - AM_PerilousAttack_Thrust ✓
- 全部 5 個 Montage 已儲存（標題欄無 "*" 符號）
</acceptance_criteria>

### Task 2 — 在 AnimBlueprint 的 Event Graph 加入監聽 + 呼叫邏輯

<read_first>
打開 BP_SekiroEnemy 的 AnimBlueprint（通常叫 ABP_SekiroEnemy 或類似名稱）
</read_first>

<action>
**步驟 1：打開 AnimBlueprint 的 Event Graph**

1. 在 **Content Browser** 找 BP_SekiroEnemy 的 **AnimBlueprint**（名字通常含 "ABP" 前綴）
2. **雙擊**打開，然後點頂部 tab **"Event Graph"**（不是 AnimGraph）

**步驟 2：加入 AnimNotify 事件節點**

3. 在 Event Graph 空白區域 **右鍵點擊**
4. 搜尋框輸入 `AN_PerilousHit`
5. 選擇 **"Event AN_PerilousHit"**（一個紅色的事件節點會出現）

**步驟 3：連接呼叫 PerformPerilousHitCheck()**

6. 從 **"Event AN_PerilousHit"** 的 **白色執行針（Execute pin）** 拖出連線
7. 搜尋框輸入 `Get Combat Component`（或 `SekiroCombatComponent`）
8. 選擇 **"Get Combat Component"** 節點（取得 CombatComponent 的引用）
9. 從 Combat Component 節點的輸出引用針**拖出連線**
10. 搜尋框輸入 `Perform Perilous Hit Check`
11. 選擇 **"Perform Perilous Hit Check"** 函數節點
12. 連接執行針：**Event AN_PerilousHit → Perform Perilous Hit Check**

**最終連線結果：**
```
[Event AN_PerilousHit] → [Get Combat Component] → [Perform Perilous Hit Check]
```

13. **Compile**（藍色 Compile 按鈕，左上角）— 確認沒有 Error
14. **Save**（Ctrl+S）

**如果搜尋 "Perform Perilous Hit Check" 找不到：**
- 確認 Context Sensitive 沒有打勾，或取消 **"Context Sensitive"** 的勾再搜尋
- 確認 C++ 已成功 Build（UE5 Build 成功才能在 BP 搜尋到 C++ 函數）
</action>

<acceptance_criteria>
- AnimBlueprint Event Graph 有 "Event AN_PerilousHit" 節點
- 該事件節點的執行針連接到 "Perform Perilous Hit Check"
- Compile 後沒有錯誤（Compile 按鈕變成綠色勾）
- 沒有 "Node Not Found" 或 "Function Not Found" 警告
</acceptance_criteria>

### Task 3 — 驗證（Play 測試）

<read_first>
確認 Task 1 + Task 2 都已完成且儲存
</read_first>

<action>
**步驟 1：進入 Play 模式**

1. 按下 UE5 的 **Play 按鈕**（工具欄的綠色三角形）

**步驟 2：觸發危攻擊**

2. 靠近 BP_SekiroEnemy，讓 Boss 的 AI 觸發危攻擊
   - 畫面右上角應出現橙色文字：`RequestAttack Pointers: IsAtk=0, Cmb0_Valid=1, SpclM=X, SpclChance=1.00`
   - 紅色文字：`[危] Perilous Attack Warning Broadcast!`

**步驟 3：驗證命中判定**

3. 在玩家角色**按住格擋**（格擋鍵不鬆手）
4. 等待危攻擊擊中
5. 應看到畫面出現：`⚠ PERILOUS HIT — UNBLOCKABLE!`（紅色 debug 文字）
6. 玩家的 HP 應該**減少**（即使格擋中仍受傷）

**步驟 4：確認時機對齊**

7. 留意危字 UI 出現的時間 vs `⚠ PERILOUS HIT` debug 的時間
8. 如果兩者相差太大（>0.5 秒），需調整 AnimNotify 在 Montage 中的位置

**預期結果：**
- ✅ 玩家格擋狀態下被危攻擊仍然受傷
- ✅ `⚠ PERILOUS HIT — UNBLOCKABLE!` 出現在畫面
- ✅ 危字 UI 與命中時機基本對齊
- ✅ 普通攻擊（非危攻擊）不受影響
</action>

<acceptance_criteria>
- Play 模式下，Boss 觸發危攻擊時出現 "⚠ PERILOUS HIT — UNBLOCKABLE!" debug 文字
- 玩家格擋狀態下 HP 仍然減少
- 普通攻擊不觸發 "⚠ PERILOUS HIT" 信息
</acceptance_criteria>

## 附：AnimNotify 時機調整指引

如果第一次測試發現危字和命中時機不對齊：

1. 打開 Montage Editor
2. **拖動** `AN_PerilousHit` 標記的位置（在 Notifies 軌道左右拖動）
3. 往後拖 = 判定更晚；往前拖 = 判定更早
4. 儲存後在 Play 模式重新測試
